Building an AI Day Trading Assistant for NASDAQ Analysis

April 27, 2026 | 8 min read

I have been interested in financial markets for a while, and I wanted to combine that interest with what I have been learning in data analytics. The result is a web-based AI Day Trading Assistant that pulls real-time NASDAQ data, computes technical indicators, and generates directional price predictions with confidence scores. This post walks through how I built it and the logic behind each component.

View Live Site

Important disclaimer: This tool was built entirely for educational purposes to explore technical analysis and data-driven decision systems. It is not financial advice. Day trading carries significant risk — studies show the majority of day traders lose money.

Architecture: Keeping It Simple

One of my goals was to build something that required no backend server. Everything runs client-side in the browser using vanilla JavaScript, which made deployment to GitHub Pages trivial. The data comes from the Yahoo Finance API via CORS proxy fallbacks, and charts are rendered using Chart.js alongside TradingView's Lightweight Charts library.

Fetching data from the Yahoo Finance API from a browser environment requires routing requests through a CORS proxy. I implemented a fallback chain so the app tries multiple proxies before giving up:

async function fetchStockData(ticker, range, interval) {
    const proxies = [
        'https://api.allorigins.win/raw?url=',
        'https://corsproxy.io/?'
    ];
    const yahooUrl = `https://query1.finance.yahoo.com/v8/finance/chart/${ticker}?interval=${interval}&range=${range}`;

    for (let proxy of proxies) {
        const response = await fetch(proxy + encodeURIComponent(yahooUrl));
        const data = await response.json();
        return formatData(data);
    }
}

The app supports 30+ NASDAQ stocks plus NQ=F futures, across six timeframes from 2-minute candlesticks up to daily charts, making it useful for both day trading and swing trading analysis.

The AI Rules Engine

The "AI" here is a weighted scoring system that evaluates six technical indicators simultaneously. Each indicator votes bullish or bearish with a weight attached, and the total score determines the final directional prediction. I find this approach interesting because it mirrors how a human trader might mentally weigh different signals before making a decision.

Indicator Weight Bullish Signal Bearish Signal
Moving Averages2.0Price > SMA20 > SMA50Price < SMA20 < SMA50
RSI1.5RSI < 30 (oversold)RSI > 70 (overbought)

Moving averages carry the highest weight (2.0) because trend alignment across the 20-SMA and 50-SMA is generally the strongest signal. Volume gets the lowest weight (0.5) because high volume alone is ambiguous without directional context from other indicators.

The total score maps to a prediction category:

Confidence: 60–95%
Score 0 to 3 → SLIGHTLY BULLISH
Confidence: 50–75%
Score = 0 → NEUTRAL
Confidence: 40%
Score -3 to 0 → SLIGHTLY BEARISH

Score ≤ -3 → BEARISH
Confidence: 60–95%

There are also three custom rule filters: a minimum volume threshold that penalizes low-liquidity signals, a multiple-confirmation requirement (3+ indicators must agree), and a trend-following filter that suppresses signals in choppy, trendless markets. These were added after I noticed the raw score alone would fire too many low-quality signals.

Price Prediction Algorithm

Beyond a directional call, the app generates a 10-period forward price projection. The approach combines five factors, each contributing a small percentage adjustment to the current price, with confidence decaying as you project further out:

  • Momentum Factor: Recent 5-period price change (±2% influence)
  • Trend Factor: Moving average alignment (±0.2% per period)
  • RSI Influence: Overbought/oversold adjustment (±0.1%)
  • MACD Signal: Momentum direction (±0.1% per period)
  • Mean Reversion: 1% pull back toward the 20-SMA
// Predicted price n periods ahead
// adjustment = sum of all five factor contributions
// decay = 1 - (n * 0.05)  — confidence drops 5% per period
predictedPrice(n) = currentPrice * (1 + adjustment * decay)

// Confidence bands widen with volatility over time
upperBound = predicted + (volatility * n * 0.3)
lowerBound = predicted - (volatility * n * 0.3)

The mean reversion component was one of the more interesting design decisions. Most stocks don't trend in one direction indefinitely — they tend to oscillate around a moving average. Adding a 1% pull toward the 20-SMA keeps projections from running too far in one direction, which produced more realistic-looking forecast paths during testing.

Candlestick Charts

I used TradingView's Lightweight Charts library to render professional-grade candlestick charts. Each candle encodes four data points (Open, High, Low, Close) in a compact visual format that traders use to spot patterns quickly.

A green (bullish) candle means the closing price was higher than the open. A red (bearish) candle means the opposite. The wicks (thin lines above and below the body) show the high and low for that period. Patterns like doji (nearly equal open and close), hammer (long lower wick), and engulfing candles (one candle completely overlapping the previous) are commonly used as entry and exit signals.

The charts support pan, zoom, crosshair hover showing exact OHLC values, and a 20-SMA and 50-SMA overlay. They also auto-resize to the window, which was important for making the tool usable on a phone.

Auto-Refresh System

Day trading analysis becomes stale quickly, so I built an auto-refresh system with configurable intervals from 30 seconds up to 10 minutes. A live countdown timer shows seconds until the next fetch, and a manual "Refresh Now" button resets the countdown. The selected interval persists across page refreshes via session storage.

Technical Indicators: A Quick Reference

Since this was also a learning project, here is a brief breakdown of each indicator used and why it matters:

Simple Moving Average (SMA)

The average closing price over N periods. A price above its 20-SMA suggests short-term upward momentum; crossing above the 50-SMA is considered a stronger trend signal. The app overlays both on the candlestick chart.

RSI (Relative Strength Index)

A 0–100 oscillator measuring the speed and magnitude of recent price changes. Readings above 70 suggest the asset is overbought (potential reversal down); below 30 suggests oversold (potential reversal up). The formula is: RSI = 100 - (100 / (1 + RS)) where RS is the average gain divided by the average loss over 14 periods.

MACD

Built from two EMAs: the MACD line (12-EMA minus 26-EMA) and a 9-EMA signal line. When the MACD crosses above the signal line the momentum is turning bullish; below is bearish. The histogram (MACD minus Signal) makes the divergence easy to read at a glance.

Bollinger Bands

A volatility envelope: a 20-SMA in the middle, with upper and lower bands placed two standard deviations away. When price touches the lower band the asset may be oversold; near the upper band, overbought. A band squeeze (bands narrowing) often precedes a sharp breakout in either direction.

What I Learned

This project pushed me to think carefully about how to combine multiple noisy signals into a single, actionable output. A few takeaways:

  • Weighting matters: Equal-weight scoring produced too many conflicting signals. Assigning higher weight to trend indicators (SMA alignment) and lower weight to volume alone cleaned up the output significantly.
  • Confidence decay is underrated: Projecting price 10 periods out without widening uncertainty bands looks misleading. The 5%-per-period decay forces the model to communicate honest uncertainty.
  • CORS is painful: Accessing a third-party API from a static site with no backend means you're dependent on proxy reliability. Multiple fallback proxies were necessary for consistent data fetching.
  • Client-side architecture has real limits: There is no way to store historical predictions or backtest performance without a backend. That is the most obvious next step.

What's Next

The most interesting future direction is replacing the rules engine with an actual machine learning model — specifically an LSTM or Transformer trained on historical OHLC and indicator data. Other enhancements I want to explore include a backtesting module to evaluate the current rules against historical data, multi-stock comparison, and a news sentiment layer that factors in headline polarity alongside technical signals.
